问题在哪

根因是 fx-compare-card.tsx 第 597 行 .filter((r) => r.settlementCurrency === effectiveHold)——卡片列表在算完全部支付方式的花费之后，先按"我持有"选的那一个币种砍掉了其它所有行，只剩同币种的 1～2 张卡互相比。

"多换 0.0%" 这句话是拿两个几乎相等但不完全相等的数字，四舍五入到小数点后 1 位显示成 0.0% —— 116.35 跟 117.51 本来就有 1.0% 的差距（HSBC 加点 1% vs Maybank 加点 0%），但卡片顶部结论行的百分比计算用了跟展示金额不同的精度基准，四舍五入之后两个本该有差距的数字在这一行显示成了 0.0%，看起来像"比了个和自己一样的东西"。

更根本的问题：即使这句话数字准确，"只在 MYR 内部比"这件事本身就不是 Remy 要的答案——她手上还有 HKD 现金（这笔本来就是 HKD 消费，用现金直接付零换汇成本）、USDT 钱包、现金 USD，这几个选项从头到尾没有出现在比价结果里，因为它们的结算币种不是 MYR。

② 比较维度改版：从"我持有同币种"改成"我手上全部支付方式各自要花多少"

核心改动

改动说明

"我持有"是一个筛选门槛：先选一个币种，只比这个币种下面配置过的支付方式

"我持有"退休成一个可选的默认排序偏好，不再是筛选门槛：不管选不选、选哪个，这趟行程「支付方式」页面里启用的全部支付方式都会参与比较——`lib/domain/fx-recommendation.ts` 的 recommendPaymentMethods() 这个纯函数本身其实早就是这么设计的（每张卡各自算出 costInCompareCurrency，互不依赖"我持有"），这层限制完全是 UI 层（fx-compare-card.tsx）自己加的一道多余门槛，删掉这道门槛、把全部 paymentMethods 传进去即可，domain 层这个纯函数不用改一行。

具体改动点

  • cardRows 的 .filter((r) => r.settlementCurrency === effectiveHold) 这一行删掉，改成不筛选、显示全部 recommendPaymentMethods() 算出来的结果。
  • compareCurrency 固定传行程本位币（这趟是 HKD），不再依赖"我持有"决定比较单位——所有支付方式无论自己结算币种是什么，最终都折算成同一个单位摆在一起比，这样才能真的回答"哪张卡最省"，不是"MYR 卡里哪张最省"。
  • "💰 我持有" 这颗下拉降级成一个次要的默认排序/高亮提示（比如"你上次用的是 XX，这次呢？"），不影响列表显示哪些行，纯粹是个记忆辅助，不是筛选条件。
  • 现金类支付方式（现金 HKD / 现金 USD）如果结算币种跟消费币种相同（这笔是 HKD 消费，现金 HKD 直接付），完全不需要换汇，花费 = 原始金额，零加点零损耗——这条路径 fx-recommendation.ts 里 requiresConversion = method.settlementCurrency !== expenseCurrency 已经处理对了，不用改。
需要 Remy 确认："我持有"这颗下拉要不要保留（哪怕只是次要排序提示），还是干脆删掉，改成默认永远按花费从低到高排？她原话没有明确要不要保留这颗下拉本身，只是明确不要"只在这个币种里比"这道门槛，两种做法都能满足这条核心要求，稿子先按"保留但降级"画，如果她觉得多余可以直接删。

④ 打平 / 极小差距时的文案规则（根治"多换 0.0%"这句废话）

差距徽章结论行/单行文案
